# Flujo de trabajo del equipo

## Ramas
- `main`: versión estable.
- `feature/nombre`: funcionalidades nuevas.
- `fix/nombre`: correcciones.
- `docs/nombre`: documentación.

## Pull Requests
1. Crear una rama desde la rama acordada por el equipo.
2. Mantener cada PR enfocado en una funcionalidad.
3. Describir objetivo, cambios y pruebas.
4. Revisar el código de otro integrante.
5. No integrar cambios que rompan la aplicación o las pruebas.

## Commits
Usar mensajes descriptivos: `feat: add applicant registration`, `fix: validate application amount`, `docs: describe loan lifecycle`, `test: cover eligibility rules`.

## Responsabilidades sugeridas
- Análisis y comunicación con Product Owner.
- Backend y reglas de negocio.
- Frontend y experiencia de usuario.
- Pruebas, integración y documentación.

Los responsables concretos se asignan entre los integrantes del equipo.
